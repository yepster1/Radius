01

Architecture

Four layers, each with one job. The rule that matters: scoring never performs I/O, and providers never contain business logic. Everything good downstream — fast tests, streaming, cheap caching, an OG image that reuses the report — falls out of that one constraint.

Providers

lib/providers/

Thin clients for Mapbox, Overpass, Census and Anthropic. Each takes primitives, returns typed raw data, and knows nothing about scores or personas.

Rule: I/O only. No business logic.

Scoring

lib/scoring/

Every formula from the spec. Takes an already-fetched dataset, returns numbers. No fetch, no Date.now(), no randomness — same input always gives the same output.

Rule: pure. Zero I/O. 100% unit-testable.

Report

lib/report/

The only place the two meet. Fetches in parallel, feeds datasets into scoring, assembles one typed Report object. Also owns caching and graceful degradation.

Rule: orchestration only. No formulas.

Components

components/

Presentation. Server components by default; 'use client' only for the three things that genuinely need it — the combobox, the map, and the history list.

Rule: render a Report. Never compute one.
02

Request lifecycle

Overpass takes 2–10 seconds and rate-limits hard. This is the single biggest threat to the thing feeling professional, so the caching and streaming story is settled up front rather than bolted on after it feels slow.

Cold and warm paths for a shared link

  E->>C: get("amenities:dqcjqcp")
  alt Warm
    C-->>E: cached amenities (instant)
  else Cold
    E->>O: 9 category queries, in parallel
    O-->>E: raw OSM elements
    E->>C: set(24h TTL)
  end
  E->>S: score(amenities)
  S-->>E: all scores (sub-millisecond)
  E-->>U: HTML shell streams immediately
  Note over E,U: Each card is its own Suspense boundary,<br/>so demographics arriving late never<br/>blocks the scores from painting
Cache keys

Everything keys off the same geohash7 that lives in the URL. One identifier is the share payload, the cache key and the OG image input.

TTLs

Amenities 24 h (shops don't move). Census 7 d (annual data). Listing angles indefinite — regenerating per view would burn tokens for no gain.

Degradation

Any single provider failing hides only its own card. A Census outage must never take down a report whose scores already resolved.

04

Why the core is pure

This is the part of the codebase a reviewer will actually read. Walk Score written as a pure function over a passed-in dataset is testable in microseconds against fixtures; the same logic written inline in a page component with a fetch in the middle is not testable at all without mocking the network.

lib/scoring/walk.ts — the shape every score follows
What this buys us
  • Tests run in milliseconds with no network and no mocks
  • Calibrating the transit constant K shows up as a test diff, not a silent score shift
  • opengraph-image reuses the identical scoring path — no drift between the shared card and the page
  • Every formula is reviewable in isolation, which is the point of publishing the methodology
Fixture strategy

Record real Overpass responses once for four reference addresses — dense urban, transit suburb, car-dependent suburb, rural — and commit them as JSON. Tests then assert real behaviour against real data shapes, deterministically and offline. These same four fixtures are what calibrate the tuning constants.

Core flow, live on Vercel

satisfies the brief

Everything the challenge explicitly asks for, deployed and working. Nothing from the differentiator tier — the goal is a real, shareable, tested product as early as possible.

  • 2geo/geohash.ts + geo/slug.ts + geo/distance.ts — round-trip tested first
  • 3providers/mapbox.ts and the /api/autocomplete proxy that keeps the secret token server-side
  • 4AddressSearch — debounced ARIA combobox, full keyboard navigation
  • 5providers/overpass.ts + scoring/categories.ts; record the four fixtures
  • 6scoring/math.ts then walk.ts, drive.ts, transit.ts, errand.ts, urbanSuburban.ts, overall.ts — TDD, one file at a time
  • 7report/buildReport.ts — parallel fetch, caching, typed Report
  • 8/a/[slug] report page with Suspense per card; ScoreTiles, NearbyList, UrbanSuburbanBar
  • 9ReportMap — Mapbox GL, pin, walk-radius ring, categorised markers
  • 10RecentSearches — localStorage, re-runnable, clearable

Gate: a stranger can open the deployed URL, search an address, get real scores on a real map, and send the link to someone else who sees exactly the same page. Green CI.
Phase 2

Differentiators

where it stops looking like a demo

The interpretation layer. All of it builds on the phase-1 scoring core without modifying it — new files, new cards, no restructuring.

  • 1scoring/noise.ts — road / rail / nightlife proxies + NoisePanel
  • 2providers/census.ts — Census Geocoder → tract FIPS → ACS; Demographics card
  • 3SchoolList — real name/level/distance, ratings visibly labelled as modelled
  • 4scoring/signals.ts — normalise every input to [0,1]
  • 5scoring/personas.ts — the five weight vectors; test that each sums to 1.0
  • 6RenterFit — persona bars, expandable to show contributing signals
  • 7scoring/flags.ts — declarative rules, each carrying its evidence string
  • 8FlagList + the 15-minute check UI showing which needs are and aren't met
  • 9/methodology — every formula rendered beside the live values for the address in view
Gate: the report answers “who is this unit for” with visible reasoning, and every derived number links to its formula.
Phase 3

Polish

portfolio finish

Independent of each other, so any one can be dropped without consequence.

  • 1opengraph-image.tsx — branded score card at the edge, reusing the same scoring path
  • 2/compare — two reports side by side
  • 3providers/anthropic.ts + ListingAngles — schema-forced, cached, and invisible when the key is absent
  • 4Accessibility and Lighthouse pass; empty, error and rural-low-data states audited
Gate: shared links unfurl as branded cards; the deployed site works fully even with no Anthropic key configured.
